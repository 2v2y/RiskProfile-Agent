# Stage9 学生协助任务包（2026-08-27）

## 1. 背景

阶段九（`operate/stage9_full`）是正式实验目录，需要学生1和学生2协助“跑模型”。
服务器环境：Qwen 通过 vLLM 提供（`http://127.0.0.1:8000/v1`，
model ID = `/DATA/models/Qwen3.8-27B`，`max_model_len=8192`）；RAG 使用本地 BGE
（`/DATA/models/bge-small-en-v1.5`，离线加载）。服务器**无外网**，禁止联网下载。

## 2. 分工摘要

| 学生 | 负责领域 | 核心任务 |
|---|---|---|
| 学生1 | 画像 / 数据口径 | 画像链路复核、字段口径解释、数据修正流程 |
| 学生2 | 检索 / 模型环境 | 服务器依赖、BGE 离线加载、Qwen 服务、真实 RAG 验证、知识库覆盖缺口 |
| 共同 | 实验执行 | 按固定命令跑 smoke / comparison / ablation / error_analysis 并填运行记录 |

详细任务见 `01_学生1_任务卡.md`、`02_学生2_任务卡.md`；运行记录统一用
`03_运行记录模板.md`；数据位置与 SHA 见 `04_数据清单与SHA.md`。

## 3. 红线（必须遵守）

1. **不改代码**：`stage9_full` 代码由实验负责人维护，发现问题把命令输出和文件路径报回来；
2. **不联网**：不下载模型、依赖、数据；模型只用服务器本地路径；
3. **不碰冻结定义**：B0–B5 定义、评价指标、gold、audit 规则、检索 top-k 均冻结，不得修改；
4. **基准答案使用纪律**：`data/gold/benchmark_gold_restricted.jsonl` 是评价基准答案，
   只用于评价阶段，不用于模型输入或人工盲评前公开；
5. **数据变更需批准**：任何数据/知识库修正必须先提交“差异说明 + 影响评估”，经实验负责人确认后
   才能替换，并更新 SHA；
6. **正式 Test**：`python -m experiments.run_test --confirm-test` 只能由实验负责人/导师执行，
   学生不做。

## 4. 运行前提

- 实验负责人先把当前 `stage9_full` 改动 `git add + commit + push`；
- 学生在服务器 `cd ~/RiskProfile-Agent && git pull`；
- 实验数据在 `~/RiskProfile-Agent/operate/stage9_full/data/`：已全部随 Git 提交
  （含 `data/gold/`），`git pull` 即可获得；
- 先装依赖（见学生2任务卡），再按顺序跑：
  `check_stage9` → `check_qwen` → `run_smoke --n 3` → 正式实验。

## 5. 回报要求

每完成一项任务，用对应任务卡里的“回报模板”回传；实验运行一律附
`llm_summary.json` 与运行目录，确保能证明“真实调用了 Qwen”。
