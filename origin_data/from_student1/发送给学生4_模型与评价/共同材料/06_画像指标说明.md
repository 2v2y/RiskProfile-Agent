# 画像指标说明

## 1. 画像对象与时间截点

每个样本表示 `entity_proxy_id × calendar_quarter`。该季度开始日作为统一 `ranking_cutoff`。画像只能读取该截点之前已经发生并达到可用时间的历史记录。

例如，2024Q2 样本的截点为 2024-04-01。2024-04-01 当日及之后开始的检查、签发的 citation 或公开的结案信息均不得进入该样本画像。

画像是对历史记录的可追溯概括，不是企业绝对安全分，也不代表事故概率。

## 2. 历史检查可用条件

一条历史检查记录进入特征必须同时满足：

1. 属于同一冻结代理实体；
2. 检查开始时间早于 `ranking_cutoff`；
3. 其标签或相关信息的 `label_available_time` 严格早于 `ranking_cutoff`；
4. 数据来自当前分析允许的快照和规则版本；
5. 未使用未来记录桥接实体。

仅发生在截点前但尚未成熟的检查不进入历史阳性或阴性计数。候选预测样本按“代理实体—季度”合并；历史画像则保留该实体过去每次合格检查，一季度内多次检查分别计数。这两个分析层级不得混称。

## 3. Context 特征

Context 只表示截点时已知的背景：

- 截点前最近一条成熟历史检查的 `context_naics_group`；
- 截点前最近一条成熟历史检查的 `context_site_state`；
- 自然季度或季节编码。

没有成熟历史时，两个历史背景字段统一记为 `UNKNOWN`。候选检查本身的行业和州在季度截点时尚不可作为历史背景，不能进入模型。M1和M2使用完全相同的 Context 编码。

## 4. Static 静态画像

### 4.1 成熟历史检查数

\[
N_i(t)=\sum_{j \in H_i(t)} 1
\]

其中，`H_i(t)` 是代理实体 `i` 在截点 `t` 前已经达到标签可用时间的历史检查集合。

字段：`history_inspections`。

### 4.2 成熟历史阳性数

\[
Y_i(t)=\sum_{j \in H_i(t)} y_j
\]

其中 `y_j=1` 表示该次检查在主观察窗内至少签发一条直接关联 citation。

字段：`history_positive_inspections`。

### 4.3 Beta-Binomial 平滑历史率

\[
R_i(t)=\frac{Y_i(t)+\alpha}{N_i(t)+\alpha+\beta}
\]

主程序在 `config.yaml` 中固定 `α=1、β=1`，不根据 Validation 或 Test 调整。无历史样本使用同一先验均值 `α/(α+β)`。

字段：`smoothed_positive_rate`。

`standard` 风险类别用于描述 citation 构成和解释案例，不进入当前 M1/M2 主模型。这样可以避免在没有完成分类覆盖率与时间可用性验证前，把人工映射混入预测特征。

## 5. Dynamic 动态画像

### 5.1 距上次检查天数

\[
D_{insp,i}(t)=t-\max\{open\_date_j:j\in H_i(t)\}
\]

无合格历史时保留缺失。模型流水线在 Train 中拟合中位数补值，并由 `SimpleImputer(add_indicator=True)` 自动加入缺失指示，不使用全体数据中位数。

### 5.2 距上次成熟阳性天数

使用最后一条 `label=1` 且 `label_available_time<t` 的检查级历史结果。无历史阳性时保留缺失，由同一 Train 预处理生成缺失指示。

### 5.3 365天和730天窗口

窗口统一采用左闭右开：

```text
[t - 365天, t)
[t - 730天, t)
```

分别计算成熟历史检查数和成熟阳性检查数：

- `inspections_365d`、`positives_365d`；
- `inspections_730d`、`positives_730d`。

窗口内检查仍须满足标签可用时间条件。

### 5.4 时间衰减历史

对历史检查按距截点的天数 `Δd` 加权：

\[
w(\Delta d;h)=\exp\left(-\ln(2)\frac{\Delta d}{h}\right)
\]

`h` 是半衰期，主程序在 `config.yaml` 中固定为365天。检查衰减总量和阳性检查衰减总量分别保存为 `decayed_inspections`、`decayed_positives`。

当前主模型不使用“重复风险标志”或“近期趋势标志”。如后续确需增加，必须在 Test 开封前另建版本、程序和独立输出，经 Validation 冻结后才能作为扩展分析；不能把它们写成当前正式画像已经实现的指标。

## 6. M1与M2的特征边界

| 模型 | Context | Static | Dynamic |
|---|---|---|---|
| M1 | 使用 | 使用 | 不使用 |
| M2 | 使用 | 使用 | 使用 |

除特征组外，两者的数据划分、缺失处理、标准化、逻辑回归配置和评价指标必须相同。这样才能把差异解释为动态画像的增量价值，而不是模型更换带来的混合效果。

## 7. 缺失与极端值

1. 原始缺失不得改写成0，除非0在业务上明确表示“计数为零”；
2. 时间间隔无历史时保留缺失并增加缺失标志；
3. 连续特征的补值参数只在 Train 拟合；
4. 是否截尾、对数变换或标准化须在 Validation 阶段冻结；
5. Test 不重新计算任何分位数、均值或缩放参数；
6. 无穷值和负计数视为错误，进入 `数据问题.csv`。

## 8. 未来信息检查

对每个特征生成程序必须验证：

- 使用的每条事件时间均早于 `ranking_cutoff`；
- 标签型历史的可用时间严格早于截点；
- 当前目标 episode 的任何 `activity_nr` 均不在自身历史集合；
- Test 特征文件没有 `label`、未来 citation 或结案字段；
- 特征计算不读取 Validation/Test 的标签分布来确定参数；
- 同一代理实体跨季度计算时没有使用未来名称/地址桥接。

## 9. 人工复算

从不同 split、行业组、历史长度和标签状态中抽取样本，在 `画像复算.csv` 逐项记录：

- 样本编号和截点；
- 进入历史集合的检查编号；
- 被排除的记录及原因；
- 手工计算步骤；
- 程序值、复算值和差值；
- 是否通过、问题编号和复核人。

正式进入模型前，所有核心画像至少覆盖有历史、无历史、窗口边界、同日事件和未成熟记录等情形。

## 10. 画像验收条件

- [ ] 每个指标有公式、输入字段、时间规则和缺失规则；
- [ ] 所有统计参数只由允许的数据集拟合；
- [ ] 未来信息测试通过；
- [ ] 人工复算与程序输出一致；
- [ ] M1/M2特征清单可机器读取并已冻结；
- [ ] 画像表不含名称、详细地址或Test标签；
- [ ] 指标说明与论文表格一致。
