# 正式字段字典

## 1. 使用方法

本字典以 `../官方资料/DOL_OSHA字段元数据_20260812.csv` 保存的65行官方元数据为依据。正式快照中的列名与该文件逐项核对，并在 `../记录表/字段检查.csv` 记录结果。后续官方元数据发生变化时，先建立新版本再调整程序。

字段按时间角色分为：

- **标识字段**：用于连接、追踪和去重；
- **候选池字段**：用于判断样本是否进入分析；
- **历史特征输入**：仅在季度截点前可用时进入画像；
- **标签字段**：只用于生成或评价目标，绝不进入特征；
- **审计字段**：仅用于数据质量和边界检查。

## 2. Inspection 逻辑字段

| 逻辑字段 | 含义 | 建议类型 | 时间角色 | 主用途 | 关键检查 |
|---|---|---|---|---|---|
| `activity_nr` | 一次检查的唯一编号 | 字符串 | 标识 | 连接 Inspection 与 Violation | 缺失、重复、科学计数格式 |
| `open_date` | 检查开始日期 | 日期 | 候选池/标签 | 确定检查季度与观察窗起点 | 无法解析、未来日期 |
| `close_case_date` | 案件关闭日期 | 日期 | 标签成熟 | 判断阴性是否具备完整观察 | 早于开始日、仍为空 |
| `naics_code` | 行业代码 | 字符串 | 候选池/Context | 生成 G1—G4 | 小数、空值、版本 |
| `insp_type` | 检查类型原始值 | 字符串 | 候选池 | 当前正式分析只纳入H；I/K排除 | H=Planned；I=Prog Related；K=Prog Other |
| `insp_scope` | 检查范围 | 字符串 | 候选池 | 确认是否实际开展检查 | A=Complete；B=Partial；C=Records；D=NoInspection |
| `why_no_insp` | 未实际检查原因 | 字符串 | 候选池/审计 | 解释和排除无检查记录 | 与 scope 的一致性 |
| `estab_name` | 单位名称 | 字符串 | 受限标识 | 构造代理实体 | 大小写、标点、简称变化 |
| `mail_street` | 邮寄街道 | 字符串 | 受限标识 | 构造代理实体 | 空值、邮政信箱、标准化 |
| `mail_zip` | 邮寄邮编 | 字符串 | 受限标识 | 提取 zip5 | 前导零、扩展码 |
| `site_address` | 现场街道 | 字符串 | 受限审计 | 邮寄地址不可用时按规则回退 | 回退标志必须保留 |
| `site_zip` | 现场邮编 | 字符串 | 受限审计 | 回退时提取 zip5 | 前导零、扩展码 |
| `site_state` | 检查所在州 | 分类 | Context | 地区背景与分层描述 | 缺失、代码表 |
| `reporting_id` | OSHA联邦或州报告辖区标识 | 分类 | 审计/描述 | 描述监管辖区，不进入当前模型Context | 不擅自解释为州计划标志 |
| `state_flag` | 官方元数据注明当前未填充的字段 | 字符串 | 审计 | 记录空值情况 | 不进入Context或模型 |
| `host_est_key` | 系统内部单位键 | 字符串 | 审计 | 与代理实体对照 | 不当作已保证稳定的企业ID |

## 3. Violation/Citation 逻辑字段

| 逻辑字段 | 含义 | 建议类型 | 时间角色 | 主用途 | 关键检查 |
|---|---|---|---|---|---|
| `activity_nr` | 对应检查编号 | 字符串 | 标识 | 与 Inspection 连接 | 孤立记录、格式 |
| `citation_id` | citation 明细或组的标识 | 字符串 | 标识 | 去重与计数 | 缺失、重复、分组规则 |
| `issuance_date` | citation 签发日期 | 日期 | 标签 | 生成主标签和可用时间 | 早于检查开始、公开时滞 |
| `delete_flag` | 当前快照的后续删除状态 | 分类 | 审计 | 描述当前状态，不进入当前标签 | 不改写历史签发事件 |
| `standard` | OSHA Standard Cited | 字符串 | 描述 | 风险主分类的正式输入 | 原值保留、格式和覆盖率 |
| `viol_type` | Violation Type | 分类 | 描述 | 描述性统计 | 官方含义核验 |

公开 Violation 主表没有通用 `risk_text`，也没有独立的citation分组字段。风险主分类以 `standard` 的版本化映射规则为主；只有存在可核验的外部公开文字时才可补充，并单独记录来源与可用时间。citation计数先按 `(activity_nr, citation_id)` 精确去重，不凭 `citation_id` 字符形式猜测组关系；组级合并只有在另有官方依据时才执行并单独记录规则版本。

罚款、申诉、整改、和解和结案后状态原则上不进入主特征，因为其产生时间常晚于排序截点。

## 4. 派生标识与队列字段

| 字段 | 定义 | 生成阶段 | 是否进入模型 |
|---|---|---|---|
| `snapshot_id` | 数据快照唯一编号 | 数据冻结 | 否 |
| `entity_proxy_id` | 由冻结的名称与地址规则生成的匿名代理实体编号 | 实体构造 | 仅作分组标识 |
| `entity_address_fallback_flag` | 是否使用现场地址回退 | 实体构造 | 主分析不使用，作审计 |
| `sample_id` | 一条单位—季度样本的稳定匿名编号 | 队列构建 | 作标识；只用于Top-k边界并列顺序，不改变AP同分组 |
| `calendar_quarter` | 样本所属自然季度 | 队列构建 | 可作 Context |
| `ranking_cutoff` | 该季度统一排序截点，默认季度开始日 | 队列构建 | 时间约束，不作结果变量 |
| `naics_group` | G1—G4 互斥行业组 | 行业筛选 | Context |
| `planned_flag` | `insp_type=="H"` | 候选池 | 不作预测特征 |
| `episode_activity_nrs` | 同一单位—季度内组成 episode 的全部检查编号 | 队列构建 | 否 |
| `episode_open_date` | episode 规定的起始日期 | 队列构建 | 标签生成，不作特征 |
| `label` | 观察窗内是否至少签发一条直接关联 citation | 标签生成 | 否 |
| `label_available_time` | 该标签最早可以合法使用的日期 | 标签生成 | 否 |
| `split` | Train、Validation、Embargo 或 Test | 时间切分 | 仅控制训练与评价 |

## 5. 画像字段

| 字段 | 类型 | 简要定义 | 截点要求 |
|---|---|---|---|
| `history_inspections` | Static | 截点前结果已经成熟的历史检查数 | 仅计 `outcome_available_time < cutoff` 的记录 |
| `history_positive_inspections` | Static | 成熟历史中签发 citation 的检查数 | 同上，一次检查多条citation仍计一次 |
| `smoothed_positive_rate` | Static | Beta-Binomial 平滑历史阳性率 | 主程序固定α=1、β=1 |
| `days_since_last_inspection` | Dynamic | 截点距上次合格历史检查的天数 | 无历史时按冻结缺失规则处理 |
| `days_since_last_positive` | Dynamic | 截点距上次成熟阳性事件的天数 | 不使用尚未成熟答案 |
| `inspections_365d` | Dynamic | 截点前365天合格历史检查数 | 区间固定为 `[t-365天, t)` |
| `positives_365d` | Dynamic | 截点前365天已成熟阳性数 | 成熟规则优先 |
| `inspections_730d` | Dynamic | 截点前730天合格历史检查数 | 区间固定为 `[t-730天, t)` |
| `positives_730d` | Dynamic | 截点前730天已成熟阳性数 | 成熟规则优先 |
| `decayed_inspections` | Dynamic | 历史检查按时间衰减后的总量 | 主程序半衰期固定365天 |
| `decayed_positives` | Dynamic | 成熟阳性检查按时间衰减后的总量 | 主程序半衰期固定365天 |

完整公式见 `06_画像指标说明.md`。

## 6. 标签与可用时间

预置主标签：对候选 episode 中每次计划性 Inspection，分别检查其自身 `open_date` 起180天内是否签发直接关联 citation；episode 只要任一组成检查符合即记为阳性，否则记为阴性。

- 阳性可用时间：全部符合记录中最早的 `issuance_date + 30天公开缓冲`。因为 episode 是“任一为真”的 OR 标签，首个阳性公开后答案已不可逆，无需等待其他组成检查；
- 阴性可用时间：所有组成检查都无符合 citation，并取 `max(各组成检查open_date + 210天, 各组成检查close_case_date)`；要求结案但任一组成检查尚未结案时，标签仍未成熟；
- 多检查 episode：标签窗口仍按每次 Inspection 自身起点计算，不使用会缩短较晚检查观察期的统一 episode 起点；
- 未达到成熟时间的记录不当作阴性；
- 主标签描述 citation issuance，不等于事故、伤亡或未经检查的真实违章。

180天观察窗和30天缓冲是正式核验前的预置协议。若官方数据中的签发时滞支持调整，必须在 Test 答案开封前更新规则版本并整体重建队列。

## 7. 禁止进入画像的字段

- 目标检查自身的结果；
- 目标检查后的 citation、罚款、申诉、整改和结案信息；
- 季度 `ranking_cutoff` 之后出现或才公开的信息；
- Test 标签或从 Test 标签反推的编码；
- 依赖未来名称变化才能建立的实体桥接；
- 含义未由官方资料核验的代码；
- 单位名称、详细地址、电话或其他不必要识别字段。
