# 《四川电力技术》论文项目：五人总任务书

暂定论文题目：**电力相关单位动态违章画像与排序方法**  

## 1. 我们要研究什么

本项目使用美国职业安全与健康管理局（OSHA）的公开检查数据，研究下面这个问题：

> 根据电力相关单位过去的检查记录，加入“最近一段时间的变化”后，能不能比只看“过去的累计总数”更好地找出下一次检查中可能出现违章记录的单位？

可以把它理解成比较两种看法：

- 静态画像：看长期累计情况，例如过去一共检查过多少次、发现过多少次违章；
- 动态画像：在长期累计情况之外，再看近期变化，例如最近一年检查次数是否增加、最近一次检查距今多久。

这里的“找出”只是把需要人工查看的对象排在前面，不是直接认定某个单位违法。我们也不预测事故、伤亡或所有单位的真实违章情况。

最后需要完成六类成果：

1. 一份来源清楚、能够核对的正式数据；
2. 一套静态画像和动态画像指标；
3. 三种固定方法R0、M1、M2的公平比较；
4. Validation（验证数据）和封存Test（最终测试数据）的完整结果、结果范围以及表现不好或判断不清的案例；
5. 可供人工复核的电力安全数据分析流程；
6. 一篇按《四川电力技术》要求完成的中文论文。

这是正式论文项目。程序、规则和记录表都已放在执行包中。五名学生的任务是按要求操作、检查、解释和记录，不能因为结果不好就临时改变研究规则。

## 2. 开始前先看懂这些词

| 词语 | 本项目中的意思 |
|---|---|
| Inspection | 一次OSHA官方检查记录 |
| Violation | 检查后产生的违章引用记录 |
| citation | 论文和数据表中对“违章引用记录”的英文简称 |
| episode | 把同一单位在同一季度的相关检查合并成一个分析样本 |
| 标签 | 我们想判断的结果，即后续检查是否出现符合要求的citation |
| 标签成熟 | 已经等到规定期限，可以确定有没有citation；仍在处理的记录不能直接算“没有违章” |
| ranking_cutoff | 每个季度开始的截止时间；计算画像时只能使用这个时间以前已经知道的信息 |
| Train | 训练数据，用来让模型学习历史规律 |
| Validation | 验证数据，用来比较方法并确定最终做法 |
| Embargo | 训练与正式Test之间暂不用于建模的缓冲时间 |
| Test | 最终测试数据，只能在方法全部确定后打开一次 |
| SHA-256 | 文件的“数字指纹”；文件内容改变后，指纹通常也会改变 |

更完整的解释见 `01_共同研究说明与术语.md`。

## 5. 所有人都不能改变的研究规则

下面的规则已经确定。学生只按规则执行，不根据结果好坏临时修改。

### 5.1 数据来自哪里

- 使用DOL/OSHA官方Inspection和Violation公开数据；
- 正式数据必须由包内下载程序取得并记录下载时间；
- `../程序/fixtures/` 中的小型样例只用于检查程序，不能用于论文结果；
- 原始数据不使用Excel覆盖保存，也不能手工增删记录。

### 5.2 研究哪些行业

我们研究四组电力及电气相关行业：

| 组别 | NAICS代码 | 大致含义 |
|---|---|---|
| G1 | `221122` | 电力配电 |
| G2 | 以`2211`开头，但不含`221122` | 其他发电、输电和配电单位 |
| G3 | `237130` | 电力和通信线路及相关结构施工 |
| G4 | `238210` | 电气承包和其他布线安装 |

四组不能重复。论文中统一称为“电力及电气相关行业”，不能把全部样本直接称为“四川电网单位”或“纯电力作业”。

当前正式分析只研究 `insp_type == H` 的计划性检查。`I`和`K`检查不进入主分析，也不能把尚未完成的扩展分析写成论文结果。

### 5.3 一个样本代表什么

- 一个样本代表一个匿名单位在一个季度的候选记录；
- 同一单位同一季度的相关检查会合并成一个episode；
- 每个季度开始日是本季度的截止时间，即 `ranking_cutoff`；
- 计算本季度画像时，只能使用截止时间以前已经公开的信息，不能“偷看未来”；
- 目标结果是后续检查在规定观察期内是否出现符合规则的citation；
- 还没有等完观察期的记录不能当成“没有违章”。

每个季度都要报告：

- 一共有多少候选样本；
- 其中多少已成熟；
- 已成熟样本中多少有citation、多少没有citation；
- 多少仍然开放或未成熟；
- 成熟样本占全部候选的比例。

模型只在已经成熟的样本上评价，因此论文结论也只能用于这部分样本。

### 5.4 数据按时间怎样分组

| 数据部分 | 时间 | 用途 |
|---|---|---|
| Train | 2015Q1—2021Q4 | 让模型学习历史规律 |
| Validation | 2022Q1—2023Q1 | 比较方法、确定最终规则 |
| Embargo | 2023Q2—2023Q4 | 训练和Test之间的缓冲区 |
| Test | 2024Q1—2025Q4 | 方法确定后的唯一正式检验 |

真正运行时，以 `../程序/config.yaml` 和 `../共同材料/02_正式字段字典.md` 为准。如果文字、配置和程序输出互相不一致，必须停止并登记问题，不能自行挑一个继续。

### 5.5 比较哪三种方法

| 方法 | 大白话解释 |
|---|---|
| R0 | 最简单的参考方法，根据经过平滑处理的历史违章比例给出分数，避免少量记录造成比例忽高忽低 |
| M1 | 使用行业、地区和长期累计信息，也就是静态画像 |
| M2 | 在M1的基础上加入近期变化信息，也就是动态画像 |

M1和M2必须使用同一批样本、同一种逻辑回归和同一套实验设置。两者最主要的区别只能是M2多用了动态画像。本文不把复杂模型当作主要贡献。

主要评价指标是：

- AP：排名靠前的位置是否更集中地出现真正有citation的样本；主结果先计算每个季度的AP，再按该季度候选数量汇总；
- Recall@20%：只查看排名最前的20%样本，可以找到全部阳性样本中的多大比例；
- Brier和校准：模型给出的分数与实际结果是否相称。

程序会以同一匿名单位为一组，进行至少2000次配对重复抽样（Bootstrap），计算95%置信区间，也就是结果可能的变化范围。学生不需要手算公式，但必须会解释“结果是否稳定”和“范围是否跨过0”。

### 5.6 Test只能打开一次

正式执行顺序是：01整理数据 → 完成单位匹配复核 → 02生成画像 → 03完成Validation并冻结模型 → 03b生成无标签Test预测 → 04打开Test。

`run_pipeline.py` 只用于获得授权后的受控复现，不是大一学生第一次执行项目的入口，也不会打开Test。

下面的命令必须从执行包根目录运行。正式Test的唯一命令是：

```bash
python3 程序/04_run_sealed_test.py --confirm-open-test
```

只有数据、画像、模型、Validation结果、评价规则和相关文件SHA-256全部确定并通过验收后，才能运行这条命令。即使运行中途失败，也会留下开封记录，本研究版本不能删除记录后重新运行。

看到Test结果后，不能再修改行业范围、标签、特征、模型、时间划分、评价指标或随机种子。

| 阶段 | 谁主要负责 | 开始前必须具备 | 做完时应该看到 |
|---|---|---|---|
| A. 下载和整理数据 | 学生1 | 运行环境和官方字段检查正常 | 数据来源、筛选、连接、排除和成熟情况都有记录 |

本项目不按周安排。前一阶段没有通过验收，后一阶段不能拿着不完整文件继续。

各阶段还要通过五个检查门：

- 门0：运行环境、官方字段和正式下载正常；

为了不让建模同学提前看到Test信息：

- 学生3负责先确定画像的定义，并检查Train/Validation画像；
- 学生1在受限数据区运行需要读取原始记录的01、02和03b；

- 学生5负责证据核对和Test开封监督；

## 8. 结果可以怎样解释

可以写：

- 在本项目收集并达到成熟条件的OSHA计划性检查样本中，加入动态画像后，排序结果相对静态画像有什么变化；
- 某些历史动态指标与后续citation之间存在统计上的联系；
- 这套数据整理和画像方法可以为国内电力安全数据分析提供方法参考；
- 排名结果可以形成待人工查看的候选线索。

不能写：

- 模型预测了所有企业、所有作业或所有人员的真实违章；
- 某个历史指标一定导致了事故或违章；
- 美国OSHA数据证明该方法已经在四川电网取得实际效果；
- 排名靠前就代表单位一定违法、危险或应该受到处罚；
- Recall@20%等于现实中一定能节省80%的检查资源；
- 只报告表现好的季度，隐藏负结果或不确定结果。

一句话原则：只说数据和实验真正支持的内容，不把“排序线索”夸大成“违法结论”或“实际应用效果”。

## 11. 遇到问题时什么时候必须停

遇到下面任意一种情况，不要猜测、跳过或偷偷修改：

- 官方字段缺失、改名或含义不清；
- 文件SHA-256与交接记录不一致；
- 行业分组出现重复或无法解释；
- Inspection与Violation连接数量异常；
- 标签还未成熟，却被当成“没有citation”；
- 画像使用了季度开始日以后才知道的信息；
- Train、Validation或Test时间范围不符合固定设置；
- 学生3或学生4提前拿到Test特征明细或答案；
- Test已经尝试打开，却有人要求删除记录后重跑；
- 论文中的数字找不到对应结果文件。

正确做法是保存现场、填写 `../记录表/数据问题.csv`、通知傅友文，并在问题解决和重新核对后继续。结果不好不是程序错误，也不能成为改规则或删结果的理由。
