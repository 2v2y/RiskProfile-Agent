# Test程序性隔离与访问规则

## 1. 边界说明

本项目使用公开数据，任何人都可以重新下载原始记录并推导检查结果。因此“封存 Test”是通过固定分工、文件权限、代码冻结、SHA-256和一次性开封记录实现的程序性隔离，不是密码学意义上的不可见盲测。论文必须如实写明这一点。

## 2. 访问分工

- 学生1是正式数据保管人：运行官方下载和数据整理，保存原始表、可重建结果的中间表及受限实体文件；不参与模型、特征、阈值或成功判据的选择，也不向建模成员透露 Test 结果。
- 学生2通常只接收 `结果/01_数据审计/风险分类输入_最小字段.csv`：匿名分类编号、`standard`、`viol_type`和汇总数量；不接收活动编号、日期、单位、split或 Test 标签明细。实体复核时仅额外接收不含这些字段的盲审候选。
- 学生3只接收 Train/Validation 画像材料；不得访问Test特征明细、原始表、检查—citation连接表或可重建 Test 结果的账本。
- 学生4只使用 Train/Validation 分析表完成模型冻结。冻结后只接收学生1在受限区生成的无标签 Test 预测及承诺；不得取得Test特征明细、原始表或 Test 标签。
- 学生5核对冻结清单和开封记录，只有唯一开封命令执行时才与学生4共同查看正式结果；实体复核时仅额外接收不含活动编号、日期、结果或split的盲审候选。

## 3. 受限文件

以下内容只在受限数据区保存，不作为普通交接材料：

- `数据/00_原始数据/` 中的官方大表；
- `数据/01_中间数据/inspection_clean.csv`；
- `数据/01_中间数据/violation_clean.csv`；
- `数据/01_中间数据/inspection_episode.csv`；
- `数据/01_中间数据/historical_inspection_outcomes.csv`；
- `数据/01_中间数据/受限_*`；
- `数据/03_封存测试/sealed_test_labels.csv`。
- `数据/03_封存测试/test_features_sealed.csv`。

普通分析交接只包含已经通过审计的 Train/Validation 画像、特征字典、防泄漏结果、Test标签／特征承诺及冻结后的无标签预测。Test特征明细不交接：后季度特征可能合法吸收已成熟的前季度Test历史，跨季度比较可能反推出部分答案。

只有两类最小必要例外：

1. 实体盲审：学生2、学生5只看去除活动编号、实体ID、日期、结果和split后的盲审表；学生3只看分歧行。三人不得拿盲审片段查询原始案件；
2. 画像复算：学生1按固定的20个Train/Validation样本生成 `结果/02_画像/受限_画像复算证据卡.csv`。证据卡只含匿名历史编号、时间、入选／排除原因、窗口位置，以及仅对成熟入选记录提供的阳性标志；不得含名称、地址、citation明细、原始活动编号或任何Test样本。

两类材料完成任务后仍按受限材料保存。

## 4. 开封前控制

1. 研究规则、特征程序、模型配置、随机种子和评价指标先冻结；
2. 学生4运行03，只用Train/Validation冻结模型、配置和 `frozen_manifest.json`，不读取Test特征或标签；
3. 学生1在受限区运行 `03b_generate_sealed_predictions.py`，验证冻结清单后读取Test特征并一次性生成无标签预测和预测承诺；
4. 学生1确认原始、Test特征和标签没有进入普通共享区；
5. 学生4（执行）、学生5（监督）和学生2（复核）完成 `记录表/测试开封记录.csv` 的开封前栏目，三人必须不同；
6. 只执行 `python3 程序/04_run_sealed_test.py --confirm-open-test`；
7. 开封后不依据结果调整主规则，也不删除不利季度。

## 5. 开封失败

`test_open_attempt.json` 一经建立，本研究版本即视为已经尝试开封。无论状态为 `success` 还是 `failed`，都不得删除记录或再次运行04。失败时保留原输入哈希、错误类型和时间，将论文状态写为“正式Test开封失败、无正式Test结论”。任何重新评价都必须使用新的研究版本和新的未来Test时间段，不能替代本版本。

若团队实际使用同一个无权限隔离的共享文件夹，应在论文局限中说明“Test结果采用程序性封存而非完全盲法”，不得声称分析人员在技术上绝对无法接触标签。
