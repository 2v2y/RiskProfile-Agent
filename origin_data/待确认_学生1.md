## 1. R1—R9 分类映射版本需要确认（待确认，阻塞阶段9）

现状：

- 你交付了 `standard_to_r1r9_mapping.csv` 和正式版 `agent_profile_whitelist.json`；
- 其中 `standard_to_r1r9_mapping.csv` 本身和《研究方案》§8.9 一致，例如 R1=电气危险与带电防护；

- 因此你自己这两份文件之间互相冲突，同时学生2的 `风险分类.csv` 也需要一起确认。

对模型的影响：

如果三份 R1—R9 映射不一致，`Retrieval Agent` 按风险类别检索时会拿到错误法规证据；`risk_category_counts`、`risk_category_unmapped_rate` 会算错；论文里 R1—R9 的定义也无法统一，Review 和 Audit 的类别判断全部不可信。

需要你做什么：

- 和学生2、学生3确认哪一份是最终冻结版；
- 给出最终文件的 SHA-256；
- 说明该版本是否已经写入 `agent_profile_whitelist.json` 和 `standard_to_r1r9_mapping.csv`。

## 2. 画像字段与 Agent Schema 的映射需要确认（待确认，阻塞阶段9）

现状：

- `profiles_train_val.csv` 和 `profile_supplement_8fields.csv` 使用 `candidate_naics_group`、`cutoff_date`、`risk_categories`、`historical_risk_categories` 等列；
- Agent 使用的 Schema 字段是 `industry_group`、`ranking_cutoff`、`historical_risk_categories`、`risk_category_counts`。

对模型的影响：

如果映射错误，画像整理模块会取不到正确字段；法规检索会用错历史标准编号；内容审查会用错数字。这会让整个 Agent 在真实数据上失效。

需要你做什么：

确认以下对应关系：

- `candidate_naics_group` → `industry_group`；
- `cutoff_date` → `ranking_cutoff`；
- `profile_supplement_8fields.csv` 里的 `historical_risk_categories` 和 `risk_category_counts` 分别对应 Schema 的哪两个字段；
- `risk_categories` 这一列是文档用中文描述，还是程序输入字段。
