## 二、实验原理

RiskProfile-Agent 的目标，是把动态风险画像转化成有官方证据、可以逐条复核的决策支持材料，而不是做违法认定、处罚建议或事故预测。

系统坚持两个基本边界：

1. 风险分数和排序由固定程序负责，智能模块不能修改风险分数、候选排序、数据划分或原始输入。
2. 智能模块只负责整理资料和解释结果，最终输出是人工复核线索，不是法律结论。

固定流程是：

```text
画像整理 → 法规检索 → 复核建议 → 内容审查(程序核对 + 独立语义审查)
                                              ↓
                              PASS / 转人工 / 拒绝
```

每句话都要有依据，证据账本用三类引用键记录来源：

- `profile:<field_name>`：来自画像字段；
- `regulation:<document_id>#<section>`：来自官方法规；
- `mapping:<rule_version>#<rule_id>`：来自分类规则。

当证据不足、数据缺失或输出冲突时，系统停止生成并转人工；出现禁止性表达时直接拒绝。这样保证系统在没有依据时真的会停下来，而不是继续编造答案。
### 代表什么
测试通过，代表“程序逻辑和格式规则”是对的：
- 四个模块的确定性逻辑正确；
- Schema 和 Pydantic 校验通过；
- 画像白名单、检索空结果、审查规则、最大轮次、失败关闭这些控制逻辑正确；
- 同一输入能稳定得到同一输出，日志和证据清单齐全。
这些测试用的是离线客户端、假模型或规则模板，不需要真正连到 Qwen。所以它们证明的是：在没有大模型的情况下，系统本身能正确运转、不会乱编。
调用 Qwen 没跑通，代表“真实模型服务”这一层没接好：
- 这是外部服务问题，不是阶段8代码逻辑问题；
- 可能出在环境变量没加载、模型名不一致、地址不对、端口不通、依赖版本等；
- 你的情况是 .env 没被程序读取，导致 Qwen 地址和模型名是空的，客户端连不上。
关键点在于：代码里 Qwen 调用失败时，Review 模块会静默回退到规则模板。所以流程看起来“跑完了”，测试也“通过了”，但实际上大模型根本没参与。也就是说，这个回退机制把连接失败“掩盖”了。
所以这两个结果分别代表：
- 测试通过 = 离线逻辑没问题，可以复现；
- Qwen 没跑通 = 真实在线模型还没有真正接入。
要让测试也能覆盖真实 Qwen，需要加一个“真连测试”：不是用假客户端，而是真的请求 /v1/models 和一次简单生成，并且断言返回的不是模板、同时没有触发回退。这样以后 Qwen 掉了，测试就能直接报出来，而不是被静默回退掩盖。
