# 发给学生3：阶段9前需要补充或确认的内容

记录日期：2026-08-23

说明：下面按是否阻塞阶段9排序。已交付的 `benchmark_cases.jsonl` 和 `red_team_cases.jsonl` 不用重复提交，只补缺项和确认结论。

## 1. `benchmark_gold_restricted.jsonl` 缺失（未交付，最阻塞阶段9）

现状：

目前只收到 `benchmark_cases.jsonl` 和 `red_team_cases.jsonl`，没有正确答案文件。

对模型的影响：

没有正确答案，阶段9只能让模型生成输出，却无法计算“无依据陈述率、法规引用准确率、安全转人工率”这些主指标，B0—B5 的对比实验无法出结果。

需要你做什么：

交付 `benchmark_gold_restricted.jsonl`，每条至少能对应到：

- `case_id`；
- 正确的画像数字或允许引用的事实；
- `gold_regulation_document_ids`；
- `gold_sections`；
- 其他评价所需的 gold 字段。

注意：该文件应放在受限区，不能混在普通 `benchmark_cases.jsonl` 里。

## 2. `benchmark_manifest.json` 缺失（未交付，阻塞阶段9）

现状：

没有评价数据集的清单文件。

对模型的影响：

没有清单，就无法核对 5337 条自动案例和 240 条异常案例的版本、数量、分层和 SHA-256；阶段7验收不完整，阶段9复现实验时也无法确认用的就是同一批题目。

需要你做什么：

交付 `benchmark_manifest.json`，至少包含：

- `benchmark_version`；
- `n_auto_cases`；
- `n_red_team_cases`；
- `stratification` 分组说明；
- `files` 和对应 SHA-256；
- `generated_at`。

## 3. `human_blind_sample.csv` 缺失（未交付，暂不阻塞阶段9但阻塞阶段10）

现状：

没有人工盲评样本。

对模型的影响：

没有盲评样本，学生5无法组织人工评价，论文里“结果是否可读、证据是否可追溯、对人工复核是否有帮助”这些结论没有数据支持。

需要你做什么：

交付 `human_blind_sample.csv`，隐藏方法名称，按有历史/无历史、不同风险分位、不同风险类别、证据充分/不足等分层抽样。

## 4. 评价案例字段定义和知识库版本需要确认（待确认，阻塞阶段9）

现状：

- `benchmark_cases.jsonl` 里的 `input_card.allowed_profile_facts` 是字符串形式；
- `required_outputs` 的字段名需要和 Agent 输出对齐；
- 案例里写的是 `knowledge_version: "4.0"`，与学生2 `knowledge_manifest.json` 里的 `4.0` 一致；但学生2的接入说明又写了 `5.0-frozen`，需要三方确认最终版本。

对模型的影响：

如果字段定义不清楚，评价程序无法把模型输出和正确答案对齐，指标会算错；如果知识库版本不一致，gold 正确答案和实际检索内容会对不上。

需要你做什么：

- 说明 `allowed_profile_facts` 和 `required_outputs` 的准确含义；
- 确认 `knowledge_version` 应统一成哪个冻结版本，并和学生2保持一致；
- 确认 `stratification.risk_category` 使用哪一版 R1—R9 映射，和学生1、学生2对齐。
